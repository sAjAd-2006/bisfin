# بخش پنجم: مقدمات پیاده‌سازی و SQL

**مرتضی امینی — نیمسال اول ۱۳۹۹-۱۴۰۰**
محتویات اسلایدها برگرفته از یادداشت‌های کلاسی استاد محمدتقی روحانی رانکوهی است.

---

# ۱. مقدمات پیاده‌سازی

برای اینکه طراحی منطقی پایگاه داده را در یک سیستم مدیریت پایگاه داده پیاده‌سازی کنیم، به یک زبان پایگاهی نیاز داریم.

در پایگاه داده‌های رابطه‌ای، یا از دید کاربردی‌تر «پایگاه داده‌های جدولی»، زبان استاندارد برای انجام عملیات پایگاهی، زبان **SQL** است.

SQL مخفف عبارت زیر است:

**Structured Query Language**

یعنی زبان پرس‌وجوی ساخت‌یافته.

دستورهای SQL به چند گروه اصلی تقسیم می‌شوند:

## ۱. DDL

**Data Definition Language**

زبان تعریف داده است. این دسته از دستورها برای تعریف، تغییر یا حذف ساختارهای پایگاه داده استفاده می‌شود.

چند دستور مهم DDL:

```sql
CREATE TABLE
DROP TABLE
ALTER TABLE
```

## ۲. DCL

**Data Control Language**

زبان کنترل داده است و برای کنترل دسترسی‌ها و مجوزها به کار می‌رود.

## ۳. DML

**Data Manipulation Language**

زبان عملیات روی داده است و برای بازیابی، درج، حذف و به‌روزرسانی داده‌ها استفاده می‌شود.

چند دستور مهم DML:

```sql
SELECT
INSERT
DELETE
UPDATE
```

نکته مهم در SQL این است که برای مقادیر متنی یا رشته‌ای از **single quote** استفاده می‌شود؛ مثلاً:

```sql
'ali'
'computer'
```

اما برای مقادیر عددی چیزی در اطراف عدد قرار نمی‌گیرد؛ مثلاً:

```sql
20
1402
```

---

# ۲. تعریف و حذف پایگاه داده و شِما

## تعریف پایگاه داده

برای ایجاد یک پایگاه داده از دستور زیر استفاده می‌شود:

```sql
CREATE DATABASE DatabaseName;
```

## حذف پایگاه داده

برای حذف پایگاه داده از دستور زیر استفاده می‌شود:

```sql
DROP DATABASE DatabaseName;
```

---

# ۳. شِما در پایگاه داده

در بسیاری از سیستم‌های مدیریت پایگاه داده، می‌توان در داخل یک پایگاه داده چند **شِما** تعریف کرد.

شِما یا Schema یک فضای نام در پایگاه داده است.

شِما می‌تواند شامل مواردی مثل:

* جدول‌ها،
* نوع‌ها،
* دامنه‌ها،
* دیدها،
* محدودیت‌ها،
* و سایر اشیای مرتبط با یک برنامه کاربردی

باشد.

وقتی اشیا در یک شِما تعریف می‌شوند، نام شِما به عنوان پیشوند نام آن‌ها در نظر گرفته می‌شود. این کار از تداخل نام اشیا در کاربردهای مختلف جلوگیری می‌کند.

مثلاً:

```sql
dbcourse.student
```

یعنی جدول `student` در شِمای `dbcourse`.

## تعریف شِما

```sql
CREATE SCHEMA SchemaName;
```

## حذف شِما

```sql
DROP SCHEMA SchemaName;
```

---

# ۴. تعریف جدول

برای تعریف جدول از دستور `CREATE TABLE` استفاده می‌شود.

ساختار کلی دستور به شکل زیر است:

```sql
CREATE TABLE TableName
(
    columnName dataType [NOT NULL | UNIQUE]
    [DEFAULT defaultOption]
    [CHECK (Condition)],
    ...
    [PRIMARY KEY (listOfColumns)],
    [UNIQUE (listOfColumns)],
    [FOREIGN KEY (listOfForeignKeyColumns)
        REFERENCES ParentTableName [(listOfCandidateKeyColumns)]
        [ON UPDATE referentialAction]
        [ON DELETE referentialAction]],
    [CHECK (Condition)],
    [INHERITS (parent-tables)]
);
```

در تعریف جدول، هم ستون‌ها مشخص می‌شوند، هم نوع داده هر ستون، و هم محدودیت‌های مربوط به جدول یا ستون‌ها.

---

# ۵. جدول موقت

گاهی می‌توان جدول را به صورت موقت ایجاد کرد:

```sql
CREATE TEMPORARY TABLE TableName (...);
```

جدول موقت داده‌های پایا ندارد. معمولاً برای ذخیره نتایج میانی استفاده می‌شود و بعد از پایان Session کاربر، توسط سیستم حذف می‌شود.

---

# ۶. انواع داده‌ای در SQL

در تعریف ستون‌ها، می‌توان از انواع داده‌ای مختلف استفاده کرد.

## داده‌های کاراکتری

```sql
CHAR(n)
VARCHAR(n)
```

`CHAR(n)` معمولاً برای رشته‌هایی با طول ثابت و `VARCHAR(n)` برای رشته‌هایی با طول متغیر استفاده می‌شود.

## داده‌های بیتی

```sql
BIT(n)
BIT VARYING(n)
```

## داده‌های عددی

```sql
NUMERIC(p, q)
REAL
INTEGER
SMALLINT
FLOAT(p)
DOUBLE PRECISION
```

## داده‌های زمانی

```sql
DATE
TIME
TIMESTAMP
INTERVAL
```

در برخی DBMSها، نوع داده‌های خاص هم پشتیبانی می‌شود. مثلاً در PostgreSQL، نوع داده جغرافیایی وجود دارد که ذخیره و پردازش داده‌های مکانی را ساده‌تر می‌کند.

---

# ۷. محدودیت‌های ستونی

در SQL می‌توان برای ستون‌ها محدودیت تعریف کرد.

## DEFAULT

برای تعیین مقدار پیش‌فرض ستون استفاده می‌شود.

```sql
DEFAULT value
```

## NOT NULL

یعنی ستون نمی‌تواند مقدار تهی یا Null داشته باشد.

```sql
NOT NULL
```

## UNIQUE

یعنی مقدارهای ستون یا مجموعه‌ای از ستون‌ها باید یکتا باشند.

```sql
UNIQUE
```

## PRIMARY KEY

کلید اصلی جدول را مشخص می‌کند. کلید اصلی می‌تواند از یک ستون یا چند ستون تشکیل شود.

```sql
PRIMARY KEY (columnName)
```

## FOREIGN KEY

کلید خارجی را مشخص می‌کند و برای ایجاد ارتباط بین جدول فرزند و جدول والد استفاده می‌شود.

```sql
FOREIGN KEY (columnName)
REFERENCES ParentTable(columnName)
```

## CHECK

برای تعیین محدودیت مقداری روی ستون یا جدول استفاده می‌شود.

```sql
CHECK (condition)
```

## INHERITS

برای ارث‌بری یک جدول از جدول دیگر استفاده می‌شود و می‌تواند برای پیاده‌سازی روابط IS-A کاربرد داشته باشد.

---

# ۸. مثال تعریف جدول درس‌ها

در این مثال جدولی به نام `COT` تعریف شده است:

```sql
CREATE TABLE COT
(
    COID CHAR(6) NOT NULL,
    COTITLE CHAR(16),
    CREDIT SMALLINT,
    COTYPE CHAR(1),
    CODEID CHAR(4),
    PRIMARY KEY (COID)
);
```

در این جدول:

* `COID` شماره درس است.
* `COTITLE` عنوان درس است.
* `CREDIT` تعداد واحد است.
* `COTYPE` نوع درس است.
* `CODEID` کد گروه یا دانشکده مرتبط است.
* `COID` به عنوان کلید اصلی تعریف شده است.

---

# ۹. مثال تعریف جدول دانشجو

```sql
CREATE TABLE STT
(
    STID CHAR(8) NOT NULL,
    STNAME CHAR(25),
    STLEV CHAR(12),
    STMJR CHAR(20),
    STDEID CHAR(4),
    PRIMARY KEY (STID),
    CHECK (STMJR IN ('bs', 'ms', 'doc', '???'))
);
```

در این جدول:

* `STID` شماره دانشجویی است.
* `STNAME` نام دانشجو است.
* `STLEV` سطح تحصیلی است.
* `STMJR` رشته یا مقطع است.
* `STDEID` کد گروه آموزشی است.
* `STID` کلید اصلی است.
* مقدار `STMJR` باید یکی از مقادیر مجاز داخل `CHECK` باشد.

---

# ۱۰. مثال تعریف جدول انتخاب درس

```sql
CREATE TABLE SCT
(
    STID CHAR(8) NOT NULL,
    COID CHAR(6) NOT NULL,
    TR CHAR(1),
    YR CHAR(5),
    GRADE DECIMAL(2, 2),
    PRIMARY KEY (STID, COID),
    CHECK (GRADE >= 0 AND GRADE <= 20),
    FOREIGN KEY (STID) REFERENCES STT (STID)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
    FOREIGN KEY (COID) REFERENCES COT (COID)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

در این جدول:

* `STID` شماره دانشجو است.
* `COID` شماره درس است.
* `TR` ترم است.
* `YR` سال است.
* `GRADE` نمره است.
* کلید اصلی از ترکیب `STID` و `COID` ساخته شده است.
* `STID` کلید خارجی به جدول دانشجو است.
* `COID` کلید خارجی به جدول درس است.
* با `ON DELETE CASCADE` اگر رکورد والد حذف شود، رکوردهای وابسته هم حذف می‌شوند.
* با `ON UPDATE CASCADE` اگر مقدار کلید در جدول والد تغییر کند، مقدار وابسته در جدول فرزند هم به‌روزرسانی می‌شود.

---

# ۱۱. حذف جدول

برای حذف جدول از دستور `DROP TABLE` استفاده می‌شود:

```sql
DROP TABLE tableName [CASCADE | RESTRICT];
```

## CASCADE

اگر جدول اشیای وابسته داشته باشد، مثل دیدها یا محدودیت‌های وابسته، آن‌ها هم به صورت خودکار حذف می‌شوند.

## RESTRICT

اگر شیء وابسته‌ای وجود داشته باشد، سیستم از حذف جدول جلوگیری می‌کند.

حالت پیش‌فرض معمولاً `RESTRICT` است.

مثال:

```sql
DROP TABLE SCT;
```

---

# ۱۲. تغییر جدول

برای تغییر ساختار جدول از دستور `ALTER TABLE` استفاده می‌شود.

با این دستور می‌توان کارهایی مثل موارد زیر انجام داد:

* اضافه کردن ستون،
* حذف ستون،
* تغییر مقدار پیش‌فرض،
* تغییر نام ستون،
* اضافه کردن محدودیت،
* حذف محدودیت.

ساختار کلی:

```sql
ALTER TABLE tableName
    ADD COLUMN columnName dataType;
```

مثلاً برای اضافه کردن ستون وضعیت به جدول دانشجو:

```sql
ALTER TABLE STT
ADD COLUMN STATE CHAR(10);
```

---

# ۱۳. شِمای پایگاهی و کاتالوگ سیستم

وقتی با دستورات DDL مثل `CREATE TABLE` ساختار پایگاه داده را تعریف می‌کنیم، سیستم این اطلاعات را در جایی ذخیره می‌کند.

این اطلاعات در قالب مواردی مثل زیر نگهداری می‌شوند:

* کاتالوگ سیستم،
* دیکشنری سیستم،
* متاداده‌ها یا فراداده‌ها.

متاداده یعنی داده درباره داده.

مثلاً اطلاعاتی درباره اینکه چه جدول‌هایی وجود دارند، هر جدول چند ستون دارد، نام ستون‌ها چیست، نوع هر ستون چیست و چه محدودیت‌هایی وجود دارد.

---

# ۱۴. آشنایی با کاتالوگ

کاتالوگ سیستم خودش معمولاً از تعدادی جدول تشکیل شده است.

مثلاً یک جدول فرضی به نام `SysTables` می‌تواند اطلاعات جدول‌ها را نگهداری کند.

نمونه اطلاعات آن:

| نام جدول | ایجادکننده | تاریخ | تعداد ستون |
| -------- | ---------- | ----- | ---------- |
| STT      | C1         | D1    | 5          |
| COT      | C1         | D2    | 5          |
| SCT      | C2         | D2    | 5          |

یعنی `SysTables` جدولی است که جدول‌ها را مدیریت می‌کند.

جدول دیگری به نام `SysCols` می‌تواند اطلاعات ستون‌ها را نگهداری کند.

نمونه اطلاعات آن:

| نام ستون | نام جدول | نوع  | طول |
| -------- | -------- | ---- | --- |
| STID     | STT      | CHAR | 8   |
| STNAME   | STT      | CHAR | 25  |
| GR       | SCT      | DEC  | 2,2 |

یعنی `SysCols` جدولی است که ستون‌ها را مدیریت می‌کند.

نکته مهم: برنامه‌ساز معمولاً نباید محتوای کاتالوگ را مستقیماً با دستورهایی مثل `INSERT`، `DELETE` یا `UPDATE` تغییر دهد. این اطلاعات باید از طریق دستورات تعریف داده مانند `CREATE`، `ALTER` و `DROP` مدیریت شوند.

# ۱۵. زبان جدولی TDBL و دستورهای DML

در زبان عملیات روی داده‌ها، چهار دستور اصلی مطرح است:

## SELECT

برای بازیابی داده‌ها.

## INSERT

برای درج داده‌ها.

## DELETE

برای حذف داده‌ها.

## UPDATE

برای به‌روزرسانی داده‌ها.

---

# ۱۶. دستور SELECT

دستور `SELECT` برای بازیابی داده‌ها استفاده می‌شود.

خروجی دستور `SELECT` خودش یک جدول است.

ساختار کلی:

```sql
SELECT [ALL | DISTINCT] item(s) list
FROM table(s) expression
[WHERE condition(s)]
[ORDER BY Col(s)]
[GROUP BY Col(s)]
[HAVING condition(s)];
```

بخش‌های مهم دستور:

* `SELECT`: تعیین ستون‌ها یا عبارت‌هایی که می‌خواهیم در خروجی باشند.
* `FROM`: تعیین جدول یا جدول‌های منبع.
* `WHERE`: شرط سطرها.
* `ORDER BY`: مرتب‌سازی خروجی.
* `GROUP BY`: گروه‌بندی سطرها.
* `HAVING`: شرط روی گروه‌ها.

## DISTINCT

برای حذف سطرهای تکراری از جدول نتیجه استفاده می‌شود.

```sql
SELECT DISTINCT columnName
FROM tableName;
```

---

# ۱۷. شرط در WHERE

در بخش `WHERE` می‌توان از عملگرهای مختلف استفاده کرد:

```sql
=
<>
>
<
<=
>=
BETWEEN
LIKE
IN
```

مثال:

```sql
SELECT STT.STID AS SN,
       STT.STNAME AS SName
FROM STT
WHERE STT.STMJR = 'phys'
AND STT.STLEV = 'bs';
```

این پرس‌وجو شماره و نام دانشجویانی را می‌دهد که رشته آن‌ها `phys` و سطح آن‌ها `bs` است.

---

# ۱۸. تغییر نام جدول یا ستون با Alias

در SQL می‌توان برای جدول یا ستون نام مستعار تعریف کرد.

مثال:

```sql
SELECT STT1.STID AS SN,
       STT1.STNAME AS SName
FROM STT AS STT1
WHERE STT1.STMJR = 'phys'
AND STT1.STLEV = 'bs';
```

در اینجا:

* `STT1` نام مستعار جدول `STT` است.
* `SN` نام مستعار ستون `STID` است.
* `SName` نام مستعار ستون `STNAME` است.

---

# ۱۹. مرتب‌سازی با ORDER BY

برای مرتب کردن نتیجه از `ORDER BY` استفاده می‌شود.

حالت پیش‌فرض، صعودی یا Ascending است.

برای مرتب‌سازی نزولی باید `DESC` نوشته شود.

مثال:

```sql
SELECT S.*
FROM S
ORDER BY SNAME ASC;
```

یا:

```sql
SELECT S.*
FROM S
ORDER BY SNAME DESC;
```

---

# ۲۰. الگویابی با LIKE

برای جست‌وجوی الگویی در داده‌های متنی از `LIKE` استفاده می‌شود.

مثال:

```sql
SELECT S#, CITY
FROM S
WHERE SNAME LIKE '%N';
```

یعنی نام‌هایی که با `N` تمام می‌شوند.

```sql
SELECT S#, CITY
FROM S
WHERE SNAME LIKE 'M%';
```

یعنی نام‌هایی که با `M` شروع می‌شوند.

```sql
SELECT S#, CITY
FROM S
WHERE SNAME LIKE '__A__';
```

یعنی رشته دقیقاً پنج کاراکتری که کاراکتر سوم آن `A` است.

در SQL:

* `%` یعنی هر تعداد کاراکتر.
* `_` یعنی دقیقاً یک کاراکتر.

---

# ۲۱. BETWEEN

برای بررسی قرار گرفتن مقدار در یک بازه از `BETWEEN` استفاده می‌شود.

مثلاً شماره قطعاتی را بدهید که وزن آن‌ها بین ۵ و ۱۵ است:

```sql
SELECT P#
FROM P
WHERE WEIGHT BETWEEN 5 AND 15;
```

این دستور معادل است با:

```sql
SELECT P#
FROM P
WHERE WEIGHT >= 5 AND WEIGHT <= 15;
```

---

# ۲۲. NULL

برای بررسی تهی بودن یا نبودن مقدار از `IS NULL` و `IS NOT NULL` استفاده می‌شود.

```sql
SELECT S#, CITY
FROM S
WHERE STATUS IS NULL;
```

یا:

```sql
SELECT S#, CITY
FROM S
WHERE STATUS IS NOT NULL;
```

نکته مهم: برای مقایسه با Null نباید از `=` استفاده کرد. یعنی این شکل درست نیست:

```sql
WHERE STATUS = NULL
```

---

# ۲۳. عملگرهای جبر مجموعه‌ها

SQL از چند عملگر مجموعه‌ای پشتیبانی می‌کند:

```sql
UNION
INTERSECT
EXCEPT
```

## UNION

اجتماع دو جدول یا دو نتیجه را برمی‌گرداند.

## INTERSECT

اشتراک دو جدول یا دو نتیجه را برمی‌گرداند.

## EXCEPT

تفاضل دو جدول یا دو نتیجه را برمی‌گرداند.

ساختار کلی:

```sql
tablename1 op tablename2
[CORRESPONDING [BY {column, ...}]];
```

نکته: در عملگرهای مجموعه‌ای، سطرهای تکراری معمولاً حذف می‌شوند؛ مگر اینکه از `ALL` استفاده شود.

مثلاً:

```sql
UNION ALL
INTERSECT ALL
EXCEPT ALL
```

شرط استفاده از عملگرهای مجموعه‌ای این است که ستون‌های دو جدول یا دو پرس‌وجو از نظر نام و نوع با هم سازگار باشند.

---

# ۲۴. مثال INTERSECT

شماره تهیه‌کنندگانی را بدهید که حداقل یک قطعه تولید می‌کنند:

```sql
SELECT S.S#
FROM S

INTERSECT

SELECT SP.S#
FROM SP;
```

یعنی شماره‌هایی که هم در جدول تولیدکنندگان `S` هستند و هم در جدول تولید قطعه `SP` آمده‌اند.

---

# ۲۵. مثال EXCEPT برای تست سازگاری

برای بررسی اینکه هر کسی که قطعه‌ای تولید کرده، باید در جدول تولیدکنندگان ثبت شده باشد:

```sql
SELECT SP.S#
FROM SP

EXCEPT

SELECT S.S#
FROM S;
```

اگر نتیجه این پرس‌وجو خالی باشد، یعنی همه تولیدکنندگان موجود در `SP` در جدول `S` هم ثبت شده‌اند.

---

# ۲۶. مثال EXCEPT

شماره تهیه‌کنندگانی را بدهید که هیچ قطعه‌ای تولید نمی‌کنند:

```sql
SELECT S.S#
FROM S

EXCEPT

SELECT SP.S#
FROM SP;
```

---

# ۲۷. توابع جمعی یا گروهی

توابع جمعی یا Aggregation Functions برای محاسبات کلی روی مجموعه‌ای از سطرها استفاده می‌شوند.

توابع مهم:

## AVG

میانگین:

```sql
AVG(column)
```

## MIN

کمترین مقدار:

```sql
MIN(column)
```

## MAX

بیشترین مقدار:

```sql
MAX(column)
```

## SUM

جمع مقادیر:

```sql
SUM(column)
```

## COUNT

تعداد:

```sql
COUNT(column)
COUNT(*)
```

`COUNT(column)` تعداد مقادیر غیر Null آن ستون را می‌شمارد.
`COUNT(*)` تعداد کل سطرها را می‌شمارد.

مثال:

بیشینه وضعیت تهیه‌کنندگان در شهرهای `c1` یا `c2`:

```sql
SELECT MAX(STATUS) AS SMAX
FROM S
WHERE CITY = 'c1'
OR CITY = 'c2';
```

---

# ۲۸. مثال‌های توابع جمعی

تعداد انواع قطعات تولیدی توسط تولیدکنندگان:

```sql
SELECT COUNT(DISTINCT P#) AS N1
FROM SP;
```

تعداد انواع قطعات قابل تولید:

```sql
SELECT COUNT(*) AS N2
FROM P;
```

تعداد کل قطعات تولیدی توسط تولیدکننده `s2`:

```sql
SELECT SUM(QTY) AS N3
FROM SP
WHERE S# = 's2';
```

---

# ۲۹. گروه‌بندی با GROUP BY

`GROUP BY` سطرهای جدول را بر اساس مقدار یک یا چند ستون گروه‌بندی می‌کند.

یعنی سطرهایی که مقدار ستون گروه‌بندی در آن‌ها یکسان است، در یک گروه قرار می‌گیرند.

مثال:

تعداد کل قطعات تولیدی توسط هر تولیدکننده:

```sql
SELECT S# AS SN,
       SUM(QTY) AS SQ
FROM SP
GROUP BY S#;
```

در این پرس‌وجو:

* سطرها بر اساس `S#` گروه‌بندی می‌شوند.
* برای هر تولیدکننده، مجموع `QTY` محاسبه می‌شود.

خروجی شبیه این خواهد بود:

| SN | SQ  |
| -- | --- |
| s1 | 280 |
| s2 | 100 |
| s3 | 203 |

نکته مهم: در بخش `SELECT` نمی‌توان نام ستونی را آورد که در `GROUP BY` نیست؛ مگر اینکه آن ستون داخل تابع جمعی مثل `SUM`، `COUNT`، `MAX` و غیره استفاده شده باشد.

---

# ۳۰. شرط روی گروه‌ها با HAVING

`WHERE` برای شرط روی سطرهاست، اما `HAVING` برای شرط روی گروه‌ها استفاده می‌شود.

مثال:

شماره تهیه‌کنندگانی را بدهید که بیش از ۱۰۰ قطعه تولید کرده‌اند:

```sql
SELECT S#
FROM SP
GROUP BY S#
HAVING SUM(QTY) > 100;
```

در اینجا ابتدا سطرها بر اساس `S#` گروه‌بندی می‌شوند، سپس فقط گروه‌هایی نگه داشته می‌شوند که مجموع مقدار تولید آن‌ها بیشتر از ۱۰۰ است.

---

# ۳۱. بازیابی از بیش از یک جدول

گاهی اطلاعات موردنیاز ما در بیش از یک جدول قرار دارد.

مثلاً می‌خواهیم نام تهیه‌کنندگانی را پیدا کنیم که قطعه `p2` را تولید کرده‌اند.

روش اول، استفاده از چند جدول در `FROM` و شرط اتصال در `WHERE` است:

```sql
SELECT SNAME
FROM S, SP
WHERE SP.S# = S.S#
AND SP.P# = 'p2';
```

اینجا در واقع یک نوع پیوند بین جدول `S` و `SP` شبیه‌سازی شده است.

---

# ۳۲. ضرب دکارتی در SQL

اگر دو جدول را بدون شرط اتصال در `FROM` بیاوریم، SQL ضرب دکارتی آن‌ها را تولید می‌کند:

```sql
SELECT T1.*, T2.*
FROM T1, T2;
```

یعنی هر سطر از `T1` با هر سطر از `T2` ترکیب می‌شود.

به همین دلیل، وقتی چند جدول را در `FROM` می‌آوریم، باید شرط اتصال مناسب بنویسیم تا نتیجه بی‌معنا و بزرگ نشود.

---

# ۳۳. عملگر JOIN

پیوند یا Join سطرهای دو جدول را که مقدار ستون یا ستون‌های مشترکشان یکسان است، به هم متصل می‌کند.

ساختار مقدماتی:

```sql
T1 [NATURAL] JOIN T2
```

در `NATURAL JOIN` سیستم ستون‌های مشترک دو جدول را بر اساس هم‌نام و هم‌نوع بودن تشخیص می‌دهد و سطرهایی را که مقدار مشترک برابر دارند، به هم پیوند می‌دهد.

مثلاً اگر جدول `T1` ستون‌های `A` و `B` داشته باشد، و جدول `T2` ستون‌های `B` و `C`، ستون مشترک `B` است. نتیجه Join شامل ستون‌های `A`، `B` و `C` می‌شود.

---

# ۳۴. مثال JOIN

نام تهیه‌کنندگان قطعه `p2` را بدهید:

```sql
SELECT SNAME
FROM S NATURAL JOIN SP
WHERE P# = 'p2';
```

این روش همان نتیجه روش قبلی را می‌دهد، اما خواناتر است.

---

# ۳۵. زیرپرسش یا Subquery

زیرپرسش یعنی یک `SELECT` درون یک `SELECT` دیگر.

به این حالت پرسش تو در تو هم گفته می‌شود.

ساختار کلی:

```sql
SELECT ...
FROM ...
WHERE column IN (
    SELECT ...
    FROM ...
    WHERE ...
);
```

پرسش بیرونی را Outer Query و پرسش درونی را Inner Query می‌گویند.

---

# ۳۶. عملگر IN و NOT IN

`IN` بررسی می‌کند که مقدار یک ستون در مجموعه خروجی زیرپرسش وجود دارد یا نه.

مثال:

نام تهیه‌کنندگانی را بدهید که قطعه `p2` را تولید کرده‌اند:

```sql
SELECT SNAME
FROM S
WHERE S# IN (
    SELECT S#
    FROM SP
    WHERE P# = 'p2'
);
```

مکانیزم اجرا به صورت ساده این است:

اول پرسش درونی اجرا می‌شود و شماره تولیدکنندگانی که قطعه `p2` تولید کرده‌اند به دست می‌آید. سپس برای هر سطر جدول `S` بررسی می‌شود که آیا `S#` آن در نتیجه پرسش درونی وجود دارد یا نه.

---

# ۳۷. ANY و SOME

گاهی به جای `IN` می‌توان از `= ANY` یا `= SOME` استفاده کرد.

مثلاً:

```sql
WHERE S# = ANY (
    SELECT S#
    FROM SP
    WHERE P# = 'p2'
)
```

یا:

```sql
WHERE S# = SOME (
    SELECT S#
    FROM SP
    WHERE P# = 'p2'
)
```

---

# ۳۸. پرسش‌های به‌هم‌بسته یا Correlated Subquery

دو پرسش درونی و بیرونی را به‌هم‌بسته می‌گوییم اگر در بخش `WHERE` پرسش درونی، به ستونی از جدول پرسش بیرونی ارجاع داده شود.

مثال:

```sql
SELECT SNAME
FROM S
WHERE 'p2' IN (
    SELECT P#
    FROM SP
    WHERE SP.S# = S.S#
);
```

در اینجا پرسش درونی به `S.S#` از پرسش بیرونی وابسته است.

تفاوت مهم این است که در پرسش‌های به‌هم‌بسته، سیستم معمولاً پرسش درونی را برای هر سطر از پرسش بیرونی یک بار اجرا می‌کند.

---

# ۳۹. عملگرهای ANY / SOME / ALL

می‌توان از ساختارهای زیر استفاده کرد:

```sql
theta ANY
theta SOME
theta ALL
```

که در آن `theta` می‌تواند یکی از عملگرهای زیر باشد:

```sql
=
<>
<
<=
>
>=
```

مثال:

شماره تهیه‌کنندگانی را بدهید که مقدار وضعیت آن‌ها بیشینه نباشد:

```sql
SELECT S#
FROM S
WHERE STATUS < ANY (
    SELECT DISTINCT STATUS
    FROM S
);
```

روش دیگر:

```sql
SELECT S#
FROM S
WHERE STATUS < (
    SELECT MAX(STATUS)
    FROM S
);
```

در روش دوم چون خروجی زیرپرسش فقط یک مقدار است، نیازی به `ANY` نیست.

---

# ۴۰. استفاده از COUNT در زیرپرسش

روش دیگر برای پیدا کردن نام تهیه‌کنندگانی که قطعه `p2` را تولید کرده‌اند:

```sql
SELECT SNAME
FROM S
WHERE 0 < (
    SELECT COUNT(*)
    FROM SP
    WHERE SP.S# = S.S#
    AND SP.P# = 'p2'
);
```

یعنی اگر تعداد رکوردهای متناظر در `SP` بیشتر از صفر باشد، آن تهیه‌کننده در نتیجه می‌آید.

---

# ۴۱. سور وجودی EXISTS و NOT EXISTS

`EXISTS` بررسی می‌کند که آیا خروجی زیرپرسش حداقل یک سطر دارد یا نه.

`NOT EXISTS` بررسی می‌کند که خروجی زیرپرسش خالی است یا نه.

مثال:

```sql
SELECT SNAME
FROM S
WHERE EXISTS (
    SELECT *
    FROM SP
    WHERE SP.S# = S.S#
    AND SP.P# = 'p2'
);
```

این پرس‌وجو نام تهیه‌کنندگانی را می‌دهد که حداقل یک رکورد در `SP` برای تولید قطعه `p2` دارند.

---

# ۴۲. عملیات ذخیره‌سازی داده‌ها

سه دستور اصلی برای تغییر داده‌ها عبارت‌اند از:

```sql
INSERT
UPDATE
DELETE
```

## INSERT

برای درج داده:

```sql
INSERT INTO table-name [(col1, col2, ...)]
VALUES (one row);
```

یا:

```sql
INSERT INTO table-name
subquery;
```

## UPDATE

برای به‌روزرسانی داده:

```sql
UPDATE table-name
SET col = value
WHERE condition;
```

## DELETE

برای حذف داده:

```sql
DELETE FROM table-name
WHERE condition;
```

---

# ۴۳. درج داده با INSERT

## درج یک سطر کامل

```sql
INSERT INTO STT
VALUES ('222', 'st2', 'IT', 'bs', 'D17');
```

## درج سطر ناقص

```sql
INSERT INTO STT
VALUES ('333', 'st3', NULL, 'ms', NULL);
```

در اینجا بعضی ستون‌ها مقدار `NULL` گرفته‌اند.

---

# ۴۴. درج گروهی

گاهی داده‌ها را از نتیجه یک پرس‌وجو وارد جدول دیگری می‌کنیم.

مثلاً ابتدا یک جدول موقت ایجاد می‌کنیم:

```sql
CREATE TEMPORARY TABLE T1
(
    STN,
    ...
);
```

سپس اطلاعات دانشجویان کارشناسی ارشد رشته کامپیوتر را در آن درج می‌کنیم:

```sql
INSERT INTO T1
(
    SELECT STT.*
    FROM STT
    WHERE STJ = 'comp'
    AND STL = 'ms'
);
```

---

# ۴۵. به‌روزرسانی با UPDATE

مثلاً تعداد واحد تمام درس‌های عملی گروه آموزشی `D11` را برابر ۱ قرار می‌دهیم:

```sql
UPDATE COT
SET CREDIT = '1'
WHERE COTYPE = 'p'
AND CODEID = 'D11';
```

---

# ۴۶. به‌روزرسانی در بیش از یک جدول

گاهی لازم است تغییر در چند جدول انجام شود.

مثلاً اگر شماره دانشجویی از `91107777` به `91104444` تغییر کند:

```sql
UPDATE STT
SET STID = 91104444
WHERE STID = 91107777;
```

و بعد باید جدول انتخاب درس هم اصلاح شود:

```sql
UPDATE STCOT
SET STID = 91104444
WHERE STID = 91107777;
```

اگر دستور دوم اجرا نشود، داده‌ها ناسازگار می‌شوند؛ چون شماره دانشجو در جدول اصلی تغییر کرده اما در جدول وابسته هنوز مقدار قبلی باقی مانده است.

البته در صورت تعریف درست کلید خارجی با `ON UPDATE CASCADE`، سیستم می‌تواند این تغییر را خودکار منتشر کند.

---

# ۴۷. UPDATE با زیرپرسش

مثلاً نمره دانشجویان گروه آموزشی `D111` در درس `COM222` در ترم دوم سال `94-95` را ناتمام اعلام کنیم:

```sql
UPDATE STCOT
SET STCOT.GRADE = 'U'
WHERE STCOT.TR = '2'
AND STCOT.YRYR = '94-95'
AND STCOT.COID = 'COM222'
AND STID IN (
    SELECT STID
    FROM STT
    WHERE STT.STDEID = 'D111'
);
```

---

# ۴۸. حذف با DELETE

مثلاً حذف یک درس برای یک دانشجوی خاص:

```sql
DELETE FROM STOCOT
WHERE STID = 88104444
AND COID = 'COM111';
```

---

# ۴۹. حذف از بیش از یک جدول

گاهی حذف یک رکورد در یک جدول، روی جدول‌های دیگر هم اثر دارد.

مثلاً حذف گروه آموزشی `D333`:

```sql
DELETE FROM DEPT
WHERE DEID = 'D333';
```

بعد ممکن است لازم باشد مقدار گروه آموزشی دانشجویان مربوط به آن Null شود:

```sql
UPDATE STT
SET DEID = NULL
WHERE DEID = 'D333';
```

این مسئله به قواعد جامعیت ارجاعی و نوع عملیات انتشار وابسته است.

---

# ۵۰. سایر امکانات SQL

جزوه در پایان اشاره می‌کند که امکانات دیگری در SQL وجود دارد که باید جداگانه مطالعه شوند، از جمله:

* پرسش بازگشتی یا Recursive Query
* SQL ادغام‌شده یا Embedded SQL
* SQL پویا یا Dynamic SQL
* نوشتن رویه یا Procedure
* نوشتن تابع یا Function
* امکانات شیء ـ رابطه‌ای
* مدیریت تراکنش
* پرسش پارامتری‌شده یا Parameterized Query

---

# جمع‌بندی نهایی جزوه

این جزوه درباره مقدمات پیاده‌سازی پایگاه داده و زبان SQL است. ابتدا توضیح می‌دهد که برای پیاده‌سازی طراحی منطقی پایگاه داده در DBMS به زبان پایگاهی نیاز داریم و SQL زبان استاندارد پایگاه داده‌های رابطه‌ای است.

سپس دسته‌بندی دستورهای SQL معرفی می‌شود: DDL برای تعریف ساختارها، DML برای عملیات روی داده‌ها و DCL برای کنترل دسترسی. در بخش DDL، دستورهای ایجاد و حذف پایگاه داده، ایجاد و حذف شِما، تعریف جدول، حذف جدول و تغییر جدول توضیح داده می‌شود. همچنین انواع داده‌ای، محدودیت‌های ستونی، کلید اصلی، کلید خارجی، Check، Default و Not Null بررسی می‌شوند.

بعد از آن، بحث کاتالوگ سیستم و متاداده‌ها مطرح می‌شود. سیستم اطلاعات مربوط به جدول‌ها، ستون‌ها، محدودیت‌ها و سایر اشیای پایگاه داده را در کاتالوگ ذخیره می‌کند.

در بخش DML، دستور `SELECT` و اجزای آن مثل `WHERE`، `ORDER BY`، `GROUP BY` و `HAVING` توضیح داده می‌شود. سپس عملگرهای مهمی مثل `LIKE`، `BETWEEN`، `IN`، `EXISTS`، `ANY`، `ALL`، عملگرهای مجموعه‌ای مثل `UNION`، `INTERSECT` و `EXCEPT`، و همچنین توابع جمعی مثل `SUM`، `AVG`، `COUNT`، `MIN` و `MAX` معرفی می‌شوند.

در ادامه، بازیابی از چند جدول با روش‌های مختلف توضیح داده می‌شود: استفاده از شرط اتصال در `WHERE`، استفاده از `JOIN`، زیرپرسش‌ها، پرسش‌های به‌هم‌بسته و `EXISTS`.

در پایان، عملیات تغییر داده‌ها یعنی `INSERT`، `UPDATE` و `DELETE` بررسی می‌شود و مثال‌هایی از درج تکی، درج گروهی، به‌روزرسانی چند سطر، به‌روزرسانی با زیرپرسش و حذف داده ارائه می‌شود.
